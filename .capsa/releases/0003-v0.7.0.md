## Highlights

An issue's `source` (§4.5) stops being a closed `ceo|system|agent` enum
and becomes an OPTIONAL `string|null` — a name and a capacity
(`"Jane Doe, maintainer"`), the same treatment `owner` already had.

## Why

`issues/0001-source-enum-assumes-a-company.md`, filed against a real
solo-maintainer project the enum couldn't honestly describe. The fix
checked whether `source` did any checkable work first — it doesn't, and
never has; no conformance rule reads it. A required field with a closed
vocabulary that gates nothing and forces a false answer when reality
doesn't fit is the same pattern already removed twice this cycle
(`platforms/`, `applies_to`). `source` is documentation, not authority or
enforcement (`insights/dev/format-is-not-enforcement.md`) — a name is
what it should hold.

## Notes

Additive: a capsule with `source: ceo` still conforms, since the enum's
old values remain valid strings and nothing is newly required.
