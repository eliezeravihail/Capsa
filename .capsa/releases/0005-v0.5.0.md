## Highlights

The capsule's directory layout becomes load-bearing. A record applies to the
node holding it and to everything beneath it (core §Placement), so what
governs any part of the system is derived by walking up to the root instead of
being discovered by traversing links. SPEC §2.7 says which of the project
format's record types bind their subtree and which only describe.

Addresses may now be relative (`./…`, `../…`), which is what makes a subtree
portable: move the directory and the references inside it still resolve.

Conformance gains two rules. Rule 13 rejects a link whose target is an
ancestor of the record carrying it — the path already says it. Rule 14 rejects
a relative address that escapes the capsule root.

## Notes

Rule 13 is a restriction, the first in this format's history. A capsule
carrying such a link conforms again as soon as it is deleted, and deleting it
loses no information. The example capsule in this repository carried one; it
is fixed here, and the validator that now catches it was calibrated against
the defect reinstated on purpose.

No new field and no new record type. §2.7 writes down what the existing types
already meant.
