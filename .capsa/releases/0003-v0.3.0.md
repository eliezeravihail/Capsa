## Highlights

The capsule becomes a graph. Core v0.2.0 adds **addresses** (internal, and
external `@capsule/path`), typed **`links`**, and **tombstones**. The project
format v0.3.0 adds **path identity** (the `NNNN-` prefix is now optional
ordering), the **component tree** and the **component record**, and
referential-integrity conformance rules.

Together these make a bounded, deterministic neighbourhood of any record
computable — a record's ancestors in the tree plus k hops over its edges —
which is what lets a consumer load the relevant part of a large capsule
instead of all of it. The query itself stays a consumer's concern; the format
gains no mechanism.

The validator gained stable finding **codes** and **severity** so an
operator's repair tool can act on `code` rather than on prose. It remains
read-only: repair is a maintenance mechanism and belongs to the operator.

## Compatibility

Additive throughout. A 0.2.0 capsule conforms to 0.3.0 unchanged — numbered
names and `id` stay legal, `*_ref` fields stay authoritative, and both the
component tree and `links` are optional.

## Known gaps

Identified and deliberately not in this release: interface/contract records,
parallel release lines (one monotonic `releases/` list cannot express a
maintained 25.x beside a 26.x), a platform axis, milestone-as-a-record, and
quantitative targets. None of them blocks retrieval, which is what 0.3.0 is
for.

`SPEC.md` has not yet moved to `project/SPEC.md` (see `project/README.md`);
it is still the project format's normative spec at the repository root.
